# REPORT — Recursive Self-Improvement on a 25.7M-Parameter GLM-Style Model

All numbers in this report come from real runs of this repository on CPU (torch 2.10.0, Python 3.12, Windows). Every run wrote a versioned JSON receipt with SHA-256 weight hashes; the raw receipts live under `runs/` and `artifacts/`.

## Result in one paragraph

A 25.7M-parameter byte-level hybrid-attention mixture-of-experts model was pretrained for 150 steps on a procedural Python corpus (loss 5.55 → 0.43, 260,158 tokens, 544.8 s on CPU). It then greedily solved 5 of 6 held-out coding families. A recursive self-improvement (RSI) ladder targeting the one failing family (`even`) sampled 16 completions per task, kept only completions that passed the executable verifier, and fine-tuned on the surviving programs. Two verified programs were enough to move held-out `even` accuracy from **0/2 to 1/2** within one cycle. The cost was severe interference: three previously-passing families regressed to failing at the final checkpoint. The interference is reported, not hidden.

## Architecture (25,730,592 parameters)

| Component | Setting |
|---|---|
| Layers | 12, rhythm L L L S (9 linear + 3 sparse attention) |
| Width / heads | 192 / 6 |
| Attention | ELU+1 linear attention with prefix sums; gathered sparse (window 32, stride 32) |
| MoE | 8 routed experts (SwiGLU, hidden 384), top-2, plus 1 shared expert |
| Residuals | 4 streams, learned input mixing and output routing |
| Tokenizer | 1 token per UTF-8 byte (vocab 260) |
| Context | 192 bytes |

Active-parameter estimate: 9,805,344 (shared expert + 2/8 of routed pool per layer).

The checkpoint-0150 model solved 5/6 held-out confirm families greedily: `square`, `absolute`, `nonnegative`, `reverse`, `list_sum` pass; `even` failed with invalid code (`return x if x = 0 else 0` — a syntax error).

## Stage 2/3 — the recursive self-improvement ladder

`scripts/train_self_improve.py --initial-checkpoint runs/pretrain-001/checkpoint-0150 --families-ladder even --cycles 3 --proposals-per-task 16 --fine-tune-steps 24 --seed 73`

Each cycle: propose → verify → distill (cumulative, deduplicated) → fine-tune → evaluate. Receipt: `runs/self-improve-even-001/training-receipt.json`.

| Cycle | Verified pairs added | Verified memory | Dev `even` pass rate |
|---:|---:|---:|---|
| 1 | 2 | 2 | 0.00 → **0.50** |
| 2 | 2 | 4 | 0.50 → 0.50 |
| 3 | 0 (stalled) | 4 | 0.50 → 0.50 |

Two self-discovered, machine-verified programs were enough to teach the model a family it had failed at pretraining.

### The interference problem (measured)

Greedy pass@1 on one unseen task per family, before vs after the ladder:

| Family | Before (step-150) | RSI cycle 1 | RSI cycle 3 (final) |
|---|---|---|---|
| even | 0 | **1** | **1** |
| square | 1 | 0 | 0 |
| absolute | 1 | 0 | 0 |
| nonnegative | 1 | 0 | 1 |
| reverse | 1 | 0 | 0 |
| list_sum | 1 | 0 | 1 |
| **Total** | **5/6** | **1/6** | **3/6** |

The mechanism is visible in the completions (see `EXAMPLES.md`): after fine-tuning on `return x % 2 == 0`, the model pattern-matched that fragment everywhere — greedy decoding emitted `return x % 2 ==== 0` for `square`. Cycle 3 recovered two families (the verified memory kept growing to 4 programs, and continued training partially re-stabilized them), but the final checkpoint remains far below the pretrained baseline on non-target families.

### What this experiment establishes and what it does not

- Established: verified self-generated data can teach a specific missing behavior in one cycle, at negligible data cost.
- Established: with a tiny verified memory and full-model fine-tuning, catastrophic interference dominates. The useful next moves are lower fine-tune learning rate, frozen-LM adapters, or much larger verified memories — none of which are implemented here.
- Not established: anything about RSI at frontier scale. This is a 25M-parameter model on a synthetic benchmark with a 192-byte context.

## Method guarantees

- **Determinism**: task generation derives from pure integer hashes; every run seeds `random`, `torch`, and CUDA explicitly.
- **Fail-closed**: checkpoints refuse to overwrite; non-finite losses raise; unknown splits/families are rejected; the AST gate admits nothing suspicious.
- **Receipts**: every entry point writes `schema_version: "1.0"` JSON with weight SHA-256 hashes, full curves, and environment info.

## Research experiments

See `artifacts/experiments/` (generated by `scripts/run_experiment_suite.sh` / `.bat`):

- **Data diversity** (`experiments/pretraining_data_diversity.py`): 8 vs 32 vs 88 unique compositional structures at fixed compute, paired seeds, exact paired sign tests with Holm correction.
- **Ordering/curriculum** (`experiments/pretraining_curriculum_order.py`): identical examples, interleaved vs blocked vs 8→88 curriculum.
- **RL design screen** (`scripts/run_rl_variant_screen.sh` / `.bat` + `scripts/analyze_rl_variants.py`): one changed choice per arm under a fixed completion budget, ranked by exact McNemar tests. A screen selects candidates; it does not establish results.
- **Vision** (`scripts/train_vision.py`, `experiments/full_25m_vision_digit_pilot.py`): see `VISION_REPORT.md`.

## Full-model vision pilot

`experiments/full_25m_vision_digit_pilot.py` attaches the GLM-style vision tower to the complete 12-layer LM loaded from the coding checkpoint (vocab expanded 260 → 263; mismatched embedding rows are re-trained). Only the vision tower, final block, final norm, and tied embedding train. No weights are saved. See `VISION_REPORT.md` for the measured result.
